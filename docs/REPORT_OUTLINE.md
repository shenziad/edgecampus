# 设计文档 / 实验报告建议结构

评分中功能正常实现占 60%，创新性占 20%，现场验收占 5%，问题回答占 5%，设计文档占 10%。报告应围绕可验证证据组织，而不是罗列代码。

1. 实验目的与任务要求
2. 需求分析与场景选择
3. 总体架构设计
   - 三平面架构
   - 双控制环
   - 模块边界与状态所有权
4. 网络设计
   - 拓扑、地址、VLAN、Trunk、EtherChannel
   - 三层路由、DHCP 与 ACL 意图
5. Edge 本地自治设计
   - 温度策略、迟滞区间
   - 断云仍运行与重连机制
6. Cloud 控制平面设计
   - 统一消息协议
   - 状态汇聚、策略下发、事件日志
7. Dashboard 与可观测设计
8. 实现过程与关键问题
   - PT ↔ 真实主机互通
   - 接口/协议不一致如何避免
   - 云端中断与状态恢复
9. 功能测试
   - 按 `docs/ACCEPTANCE.md` 的测试矩阵逐项写预期、操作、结果、截图解释
10. 创新性分析
   - 网络策略强制控制路径
   - Edge Local Loop + Cloud Global Loop
   - Policy Delivery 与 State Sync
11. 现场验收与问题回答准备
12. 分工与 AI 协作记录
13. 总结与改进方向

每张截图后必须写：观察到什么、为什么能证明该功能、对应哪条验收要求。避免只写“结果如图所示”。
